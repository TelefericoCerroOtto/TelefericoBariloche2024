# TB-113 report-history UX
Objective: make the existing administrative report history understandable to nontechnical operators, including shared presentation metadata and global hiding of failed rows.
Branch: `feat/app-cms-root-tb-113-report-history-ux`. Delivery: one implementation PR to `development` (`single-pr`; forecast ~900 authored changed lines, within the TB-113 standing 6,000-line exception). Runners: app Vitest/Playwright and CMS Node tests; independent security/data verifier.

## Specs

- S1 — Replace technical first-column content. User: "Los doc ID hay que sacarlos a la mierda" and "nombre y nombre editable también". Names are shared, editable presentation metadata; the PDF and report identities remain immutable. Existing rows receive a readable fallback.
- S2 — Simplify date columns. User: "La columna 'período anterior', yo honestamente la retiraría" and "la fecha de inicio y la fecha de fin también se separan con un guion y no se percibe muy bien visualmente desde cuándo hasta cuándo es el período". Preserve the report range and show generation time as secondary information rather than a prominent column.
- S3 — Make volume scannable. User: "los pondría uno debajo del otro" and replace "No disponible para este estado" with "No disponible".
- S4 — Make states human-readable. User: "en cola y en curso ... unificar eso en un solo estado visual" and "fallido y ... completado: rojo y verde respectivamente". Retain distinct backend states; use restrained processing animation with reduced-motion support. Do not expose the server's English error message to operators.
- S5 — Clarify actions. User: "el estilo del botón tiene que acompañar la acción y también se tienen que utilizar iconos" and "Inclusive el estado que no tiene un botón debería mostrarlo, pero con un estado de deshabilitado". Keep the existing queued-only cancellation and PDF/retry behavior. Do not invent cancellation of a running worker. Preserve a coherent action cell for every state.
- S6 — Remove the status filter, retain ordinary pagination and manual refresh for now. User: "Este filtro lo veo completamente inútil" and "Yo en un futuro, ahora no, quiero implementar actualización en tiempo real".
- S7 — Allow hiding a failed generation from the shared operator-facing history without deleting its Strapi record. User: "no significa eliminar el registro en Strapi"; "Para todos"; "Con costo me refiero a cuanto codigo se implementa". Choose the smallest shared persistent implementation, not user-specific preferences. Keep support/audit evidence intact, filter before count and pagination, reject hiding nonfailed records.
- S8 — User explicitly approved using the staging screenshot and their criteria as the visual reference instead of unavailable OpenDesign evidence: "Si". Record the intentional visual-reconciliation deviation in the TB-113 direct implementation ledger. Do not modify the real-time refresh behavior or add local preview/seed code.
- S9 — Commit and publish an implementation PR when checks finish. User: "Termina de implementar lo que haga falta de lo que te haya pedido en el pedido original y una vez que termines, haz commit e implementation PR." Promotion remains a separate later step.
- S10 — Access correction, explicitly authorized as ad hoc scope on this branch. User: "De donde sacaste que Administrator tiene que tener acceso a eso? En una sesion de trabajo habia quedado con mi agente que el unico que iba a tener acceso a eso era Digital Experience Operator." and "Corregi tambien lo documentado, se meten en esta rama esos cambios, sale ad hoc". Digital Experience Operator alone may access feedback; Administrator must not retain capability, direct-page access or new Strapi operatorPresentation grant. Preserve non-feedback Administrator features. Record every ad hoc path/work unit in the implementation PR's Scope Disclosure.
