# TB-113 report-history confirmations
Objective: replace report-history browser/inline confirmations with accessible HeroUI v2 modals while excluding failed attempts from server-side overlap confirmation.
Branch: `fix/app-root-tb-113-report-history-modals`. Delivery strategy: exception-ok under the user's standing TB-113 preference for complete logical PR units up to 6,000 authored changed lines; any PR remains separately authorized. Forecast ~450 authored changed lines. Test runner: focused app Vitest and typecheck; independent verifier for consumed command/concurrency contracts.

## Specs

- S1 — The failed-row `Eliminar` action opens a HeroUI v2 modal rather than `window.confirm`. User's exact message: "Está seguro que quiere eliminar este informe?". The modal MUST NOT mention Strapi, implementation details, or effects on other users. The action remains `hide` for failed generations only; no stored report or generation is deleted.
- S2 — A new generation overlapping a failed or hidden generation MUST NOT require overlap confirmation. User: "si yo quiero volver a generar un informe y se solapa con la fecha de un informe fallido, entonces el modal ... no debería aparecer" and "Querer generar un nuevo informe con algo que ya falló no es solapamiento, es simplemente una corrección". Apply the filtering at the server preflight and digest, not just in the browser. Preserve the existing exact-range queued/running conflict guard and retry route.
- S3 — When a confirmed report does overlap, open a HeroUI v2 modal instead of the inline warning and checkbox. User: "no está en un modal y tiene un checkbox horrible" and "mostrar los nombres, listar esos nombres". List the same displayed report names as the history (custom displayName or existing `Informe - <date/time>` fallback); do not show raw run IDs or date-range intersections. Provide a cancel/adjust action and one explicit generate-anyway action that submits the current overlap digest.
- S4 — User treated deletion of successful reports as optional ("para mantenerlo más sencillo, también existe la opción de no permitir eliminar informes que no fueron fallidos"). Assumption for this unit: keep `Eliminar` on failed rows only; do not add successful-report hiding or alter immutable PDF/download behavior.
- S5 — Replace the struck-eye icon on `Eliminar` with a trash-can icon; keep current date selection, successful report actions, manual refresh, and protected authentication/authorization. Update help/docs when a visible command or message changes. HeroUI v2 Modal supplies focus containment, escape handling and return focus.
