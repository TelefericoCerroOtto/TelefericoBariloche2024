# Implementation PR Command

Read `.agents/skills/implementation-pr/SKILL.md` FIRST. It owns authorization, minimal local/remote fact gathering, publication decisions, and operation-specific checks. Do not invoke `delivery-state-mapper` or start generic SDD discovery.

Bare `/implementation-pr` is strict-scope by default and itself explicitly authorizes at most one commit of the current candidate when needed, one non-force push of `HEAD` to `origin`, and creation of one implementation PR. It defaults to `origin/development`; no second consent or credential/session prompt is required for this default. Exactly `/implementation-pr --allow-mixed-scope` authorizes the same bounded publication and selects known non-sensitive paths outside the addressed item for disclosure. An explicit natural-language scope selection may also include known non-sensitive ad hoc paths and use the same disclosure. No justification is required; unknown or extra arguments and alternate spellings are rejected. An explicit natural-language request naming implementation-PR publication is also supported. A generic request to continue, ambient command, or SDD slice-transition selection does not authorize publication; SDD slice-transition publication requires independent user consent. Do not create, switch, or delete branches as part of this shortcut.

A target other than `origin/development` is allowed only when the current request explicitly selects a separately validated `stacked-to-main` preview plan. The preview must be same-repository and draft, and target only its exact immediate parent branch at the exact parent head SHA declared in the complete visible `Chain Context`. Never infer preview selection from the current or ambient branch; never accept an arbitrary base.

Capture local repository, branch, `HEAD`, Git status, candidate paths, and the selected base facts once with native Git. The default is `origin/development`; a different base is allowed only for an explicitly selected preview validated against its exact immediate parent branch and head SHA. Validate the complete path list once with `node .github/scripts/implementation-candidate-paths.js <candidate-path...>` using argument-vector execution. This checks names only; never read `.env` or other credential/secret files or their values. Stop for an unknown or secret-like candidate path, incorrect repository/branch/remote/base, an existing open PR, or ambiguous/failing commit or push. Use only the required repository-scoped GitHub reads through the current active CLI session; never read credentials or probe authentication. Runtime tool permissions remain in force. Missing capability, permission denial, or operation errors stop the workflow; do not bypass them.

Block secret-bearing `.env*` files, `.npmrc`, `.netrc`, `.pypirc`, `.ssh`, `.aws`, credentials/secrets/private-key paths, and token/auth/service-account basenames. Only exact `.env.example`, `.env.sample`, or `.env.template` basenames under non-sensitive ancestors are path-safe templates; never infer anything about their contents.

For selected ad hoc scope, disclose the complete known non-sensitive inventory in one visible English `## Scope Disclosure` section headed `Changes outside the addressed item:` and list each exact path/work unit. Do not request a reason or repeat approval per path. The bounded invocation authorizes publication, while disclosure only selects the candidate scope and does not authorize separate tracking changes. Do not generate a candidate fingerprint. Use Git-native facts, existing hooks, and CI for integrity.

Preserve validated same-repository `stacked-to-main` preview restrictions and visible `Chain Context`. Render the parent SHA as `Parent head SHA: [<full SHA>](https://github.com/<owner>/<repo>/commit/<full SHA>)`; never accept an arbitrary base.

Do not invoke standalone `branch-pr` preflight. Reuse only its repository-policy interpretation and PR-content/creation clauses inline after this workflow's candidate and safety checks. It must not repeat discovery, authorization, branch/base setup, candidate classification, fetch, or push planning. Read back the created PR and verify its head/base and target mode match the published commit and selected plan. A preview must target only its exact immediate parent branch, be draft, and include the validated `Chain Context`; any published head/base mismatch is terminal. A terminal result cannot be replayed against a new candidate under the same invocation.

Observe governance once with `node .github/scripts/wait-for-implementation-governance.js <pr-number-or-url>`. After that helper returns—whether it passes, fails, times out, or reports an observer error—run `.github/scripts/implementation-pr-vitest.js` exactly once. Report Vitest and functional/Cloud Build status as advisory evidence; do not retry an unknown/failed observation. Advisory evidence is never a publication gate.
